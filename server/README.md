# Сервер Oblox 2

Версия сервера — **2.1.1**. Запуск: `npm ci`, затем `npm start` (Node.js 18+). Сервер слушает порт 8080 на всех интерфейсах; `PORT` и `HOST` меняют адрес. Проверка версии: `GET /api/health` → `{ "service": "oblox-community", "version": 2 }`.

`OBLOX_DATA_DIR` задаёт папку постоянных данных, по умолчанию это `server/data`. Аккаунты, хэши сессий, друзья, заявки и опубликованные миры сохраняются в `community.json` атомарной заменой после записи на диск. Пароли хранятся как salted scrypt, сами токены сессий — только как SHA-256. Данные сохраняются после перезапуска. Нужен **один процесс** сервера на одну папку: это локальное файловое хранилище, не кластерная база. Повреждённый файл не сбрасывается: сервер останавливается, чтобы его можно было восстановить из резервной копии. Резервные копии папки данных делайте при остановленном сервере.

Друзья и каталог общие для клиентов, которые подключены к одному этому серверу. Для друзей через интернет нужны общий сервер, постоянное хранилище и HTTPS/WSS; локальный запуск сам по себе не размещает игру в интернете. В локальной сети клиенты указывают адрес компьютера с сервером. Приватные данные из `server/data` не публикуйте.

## Бесплатное размещение с PostgreSQL

`DATABASE_URL` включает PostgreSQL вместо локального JSON. Для Render Free используется внешняя база Neon Free: бесплатный Render не сохраняет файлы после остановки или перезапуска. `OBLOX_REQUIRE_DATABASE=1` запрещает запуск без `DATABASE_URL`, чтобы ошибка настройки не включила временное файловое хранилище. Строку подключения задавайте только в секретной переменной окружения сервиса; не добавляйте её в Git, клиент игры, APK или журналы. Для облачной базы сертификат TLS проверяется. Незашифрованное соединение допускается только с loopback-адресом и явным `sslmode=disable` для локальных тестов. Локальные аккаунты автоматически в облачную базу не переносятся.

Данные сохраняются транзакционно. Ответ об успешной регистрации, дружбе или публикации отправляется после подтверждения COMMIT. Блокировка строки и номер ревизии защищают от потери изменений при одновременных запросах и пересечении старого и нового процессов во время обновления. Основной снимок содержит аккаунты, сессии и метаданные игр; геометрия и UI опубликованных игр лежат отдельно в `oblox_game_payloads` и загружаются при скачивании конкретного мира. Presence и список друзей проверяют только ревизию и используют кэш, когда данные не изменились. Это снижает расход бесплатного трафика базы. Основной снимок ограничен 32 МиБ, HTTP-тело — 2 МиБ. Комнаты игроков находятся в памяти одного процесса; для игрового сервера используйте один экземпляр.

`/api/health` отдаёт 503 до готовности хранилища или при ошибке доступа к нему. После сбоя входящие проверки могут повторить подключение не чаще раза в 10 секунд; исправный health endpoint базу не опрашивает. Постоянных запросов для удержания Neon активным нет. Render Free засыпает после 15 минут бездействия; первый запрос после простоя запускает его примерно за минуту. Доступность ограничена бесплатными квотами провайдеров. Официальные условия: [Render Free](https://render.com/docs/free), [Neon Free](https://neon.com/pricing).

## API

Все тела — JSON. Защищённые запросы используют `Authorization: Bearer TOKEN`. Сессия действует 30 дней, до 10 сессий на аккаунт.

- `POST /api/auth/register`, `POST /api/auth/login`: `{username,password}` → `{token,user,expires_at}`. Имя: 3–20 латинских букв/цифр/подчёркиваний, уникальное без учёта регистра; пароль: 8–128 символов.
- `GET /api/auth/me` → `{user}`. `POST /api/auth/logout` отзывает текущую сессию.
- `POST /api/presence` поддерживает статус онлайн в меню. Вызывать примерно раз в 30 секунд; через 70 секунд без активности статус исчезает. Реальный WebSocket игрока даёт статус `ingame`, мир и номер сервера. P2P не сообщает присутствие в игровом мире этому серверу.
- `GET /api/users?q=имя` ищет зарегистрированных пользователей (от двух символов, до 50 результатов).
- `GET /api/friends` → `{friends,incoming,outgoing}`. Все элементы — пользователи `{id,username,name,seed,status,online,world,server,relation}`.
- `POST /api/friends/requests`: `{user_id}` отправляет заявку. `POST /api/friends/requests/:userId/accept` принимает входящую заявку. `DELETE /api/friends/:userId` удаляет дружбу, отменяет или отклоняет заявку. Операции возвращают актуальные три списка. Дружба взаимная, до 500 друзей.
- `GET /api/games` → `{games}` с метаданными, поиск `?q=...`.
- `GET /api/games/:id` → `{game,creation}` с полным миром для загрузки.
- `POST /api/games`: `{creation:world}` → `{game,creation}`. Для обновления передайте в мире `published_id` (также принимается `remote_id`). Менять мир может только автор. Полученные `game.id` и `creation.published_id` — общий ID публикации.
- `DELETE /api/games/:id` снимает собственную игру с публикации.

Публикуемые миры содержат только поддерживаемые типы деталей, UI, событий и действий. Проверяются размеры, конечность координат, интервалы таймеров, уникальность имён, наличие Spawn. Ограничения: тело до 2 МБ, до 1000 деталей, 100 элементов UI, 2000 действий, 100 игр на автора. Произвольные скрипты и файловые пути не принимаются. Метаданные автора задаёт сервер.

WebSocket `hello` поддерживает `token`; имя и `user_id` берутся из аккаунта. Гость не может занять зарегистрированное имя: получает префикс `Guest_`. Для общего опубликованного мира используйте `world: "creation:<published_id>"`; несуществующие публикации не допускаются. Старые комнаты, чат, статистика и тестовая оплата сохранены.

## Проверки

`npm test` самостоятельно запускает временный сервер с отдельными данными, проверяет регистрацию и вход, поиск и взаимную дружбу, presence и защиту имени, публикацию/скачивание/обновление, защиту авторства, валидацию, сохранение после перезапуска, удаление и выход. Затем запускает исходную проверку комнат, чата и тестовой оплаты. Рабочие данные не затрагиваются.

`npm run test:postgres` требует отдельную **одноразовую** базу с именем `oblox_test` или `oblox_test_*` в переменной `OBLOX_TEST_DATABASE_URL`. Этот тест удаляет таблицы `oblox_community`, `oblox_game_payloads` и тестовую функцию; никогда не направляйте его на рабочую базу. `DATABASE_URL` как запасной адрес не используется. Проверяются два одновременных процесса, уникальность имени без учёта регистра, дружба и сессии между процессами, параллельные публикации и ревизии, сохранность геометрии/UI, отзыв сессии при WebSocket hello, ошибка непосредственно при COMMIT и восстановление health. Отдельная проверка большого мира подтверждает, что 20 запросов presence/друзей не скачивают снимок или геометрию и получают менее 2 КиБ строк из базы. `test_pg_metrics.js` — вспомогательный preload только для этого теста; `npm start` его не загружает. Обычные файловые тесты принудительно отключают облачную базу независимо от переменных окружения.

Оплата осталась в исходном тестовом режиме. Новый сервер аккаунтов не превращает тестовый магазин и локальный баланс в проверенный платёжный продукт.

## Запуск из игры и обнаружение в домашней сети (2.1)

Для Windows рядом с проектом добавлен `Start-Server.ps1`. Клиент может запустить его скрыто через `powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File ПУТЬ/Start-Server.ps1 -NonInteractive -Port 8080`, затем проверить публичный `/api/health`. Скрипт не запрашивает ввод, возвращает код 0 для работающего сервера и 1 для ошибки; подробный результат — `server/logs/startup-status.json`. `Start-Oblox2.cmd` использует тот же помощник. Mutex сериализует одновременные запуски, существующий совместимый сервер повторно используется. Поиск Node.js проверяет переносимый `runtime/node.exe` или `server/runtime/node.exe`, затем установленные варианты; требуется версия 18+.

`/api/health` возвращает `service: oblox-community`, `version: 2`, `build: 2.1.1`, `ready`, тип `storage`, стабильный `instance_id`, фактический HTTP `port`, `ws_path` и `capabilities`. Добавление `instance_id` в прежнее хранилище не меняет существующие аккаунты, сессии, дружбу или игры. Один писатель локального хранилища защищён `server/data/server.lock`; после аварийной остановки проверяется PID и снимается устаревшая блокировка. SIGINT/SIGTERM завершают сервер корректно. При запуске из собственного Node.js супервизора с IPC можно послать приватное сообщение `oblox:shutdown`; сетевого API остановки нет.

Сервер отвечает на UDP **18881** для обнаружения в локальной сети. Порт меняется `OBLOX_DISCOVERY_PORT`; значение `0` отключает обнаружение. Запрос до 256 байт: `{"service":"oblox-discover","version":1,"nonce":"случайная-строка"}`. Nonce должен состоять из 1–64 латинских букв, цифр, `_` или `-`. Ответ содержит `service`, `version`, `build`, `instance_id`, `port`, `ws_path`, `name` и тот же `nonce`. Данные аккаунтов и токены не передаются. Клиент использует IP отправителя пакета, проверяет nonce, затем проверяет identity HTTP-запросом `/api/health`. Ответы ограничены частными IPv4 адресами и частотой; при недоступности UDP остаётся ручной ввод адреса сервера. Настройки брандмауэра скрипты не изменяют.

Стабильное поле `error_code` в HTTP ошибках позволяет интерфейсу переводить сообщения: `invalid_fields`, `username_taken`, `invalid_credentials`, `session_expired`, `rate_limited`, `forbidden`, `not_found`, `validation_failed`, `invalid_json`, `payload_too_large`, `conflict`, `storage_error`. Ошибки старта помощника: `node_missing`, `server_dependency_missing`, `server_files_missing`, `server_port_in_use`, `server_start_busy`, `server_start_failed`.

`node server/test_runtime.js` дополнительно проверяет UDP-обнаружение, стабильность identity после перезапуска, отказ второго писателя, понятные ошибки JSON и размера HTTP тела, изоляцию испорченного/слишком большого WebSocket пакета и корректную остановку. Эти проверки используют временные папки данных. `npm test` запускает оба набора проверок.
