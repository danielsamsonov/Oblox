# Oblox 2: сервер в интернете, работающий при выключенном ПК

Этот пакет содержит только исходники сервера и настройки размещения. **Публичный сервер ещё не создан, действующего интернет-адреса в пакете нет.** Для запуска нужен аккаунт у хостинга и отдельное подтверждение создания платных ресурсов. Локальный `127.0.0.1` не доступен друзьям через интернет и прекращает работать вместе с компьютером.

## Render Blueprint

В корне этого пакета лежит `render.yaml`, а код — в `server/`. Структура рассчитана на Git-репозиторий с этими файлами: `rootDir: server` уже задан правильно.

1. Создайте репозиторий из распакованного пакета без добавления личных файлов, базы или ключей.
2. В Render подключите репозиторий как Blueprint, выбрав корневой `render.yaml`.
3. Перед подтверждением проверьте платные ресурсы: web service плана `0.5c-512mb` и постоянный диск 1 ГБ. Шаблон не является бесплатным размещением.
4. После запуска откройте настоящий адрес, который выдаст Render, с путём `/api/health`. Ответ должен содержать `service: oblox-community`, `version: 2`, `build: 2.1.0`, `instance_id`.
5. В Oblox на ПК и Android выберите подключение через интернет, укажите **один и тот же полученный адрес** с префиксом `wss://` и окончанием `/ws`, затем зарегистрируйтесь или войдите в аккаунт этого сервера.

Сервер работает на компьютерах хостинга; ваш ПК после размещения не обязан оставаться включённым. Само размещение в этой сессии не выполнялось. Доступность зависит от состояния выбранного хостинга.

Настройки шаблона:

- Node.js 24 LTS, установка `npm ci`, запуск `node server.js`.
- Проверка состояния `/api/health`, HTTP-порт выдаёт Render через `PORT`.
- `OBLOX_DATA_DIR=/var/data/oblox` совпадает с точкой подключения постоянного диска.
- `OBLOX_DISCOVERY_PORT=0`: обнаружение в домашней сети не требуется облачному серверу.
- `PAYMENTS=mock`: магазин остаётся тестовым, реальные деньги не списываются.
- `TRUST_PROXY_HOPS=0`: клиентские forwarding-заголовки по умолчанию игнорируются.

Один диск использует один процесс. Аккаунты, дружба, сессии и опубликованные игры сохраняются в `community.json` на диске. Делайте резервные копии. Локальные аккаунты вашего компьютера в этот пакет не включены; новый облачный сервер начинает с пустой базы. Автоматического переноса личной базы или паролей нет.

Render сохраняет данные только в подключённом постоянном диске; подробности — [Persistent Disks](https://render.com/docs/disks) и [Blueprint specification](https://render.com/docs/blueprint-spec). План `0.5c-512mb` указан в [Compute Plans](https://render.com/docs/compute-plans). Node.js 24 указан как LTS в [официальном списке релизов](https://nodejs.org/en/about/previous-releases).

## Необязательный Docker

Из корня пакета:

```sh
docker build -t oblox-server ./server
docker volume create oblox-data
docker run -d --name oblox-server --restart unless-stopped -p 8080:8080 -v oblox-data:/data oblox-server
```

Постоянные данные находятся в Docker volume `oblox-data`. Образ использует непривилегированного пользователя `node` и содержит HTTP healthcheck. Docker на компьютере подготовки отсутствует: контейнерный образ здесь не собирался, конфигурация требует проверки на выбранном хосте. Код сервера и аварийный перезапуск проверены локальными Node.js тестами.

Для безопасного публичного подключения нужен HTTPS/WSS reverse proxy и домен либо адрес платформы. Если перед сервером свой proxy, настройте его WebSocket upgrade и сохранение заголовков. Не открывайте небезопасный HTTP с паролями в публичный интернет.

## Лимиты за reverse proxy

Без явной настройки лимиты используют IP прямого TCP-соединения. За хостинговым proxy несколько пользователей могут попадать в одну группу лимитов. `TRUST_PROXY_HOPS` позволяет учитывать проверенные IP из `X-Forwarded-For`, считая справа. Включайте его только для закрытого от прямого доступа порта и после проверки реальной цепочки proxy своего размещения. Неверное число доверенных переходов может позволить подделку IP. Шаблон не включает доверие автоматически, потому что без реального размещения цепочка не проверена. Принцип описан в [официальной документации Express](https://expressjs.com/en/guide/behind-proxies/); приложение использует собственную минимальную проверку адресов, Express не требуется.

## Состав пакета и проверки

Пакет собран по явному списку файлов. В нём нет `server/data`, журналов, токенов, личных профилей, `node_modules`, `.env` и ключей. Зависимости устанавливаются из `package-lock.json` командой `npm ci`.

Проверки: `cd server`, `npm ci`, `npm test`. Они используют временные данные и проверяют регистрацию, поиск и дружбу, публикацию, права автора, восстановление после перезапуска, комнаты и чат. Дополнительный набор проверяет UDP-протокол, ошибки HTTP/WebSocket, блокировку второго писателя, SIGKILL и повторное использование PID контейнером. Повторный PID больше не мешает запуску с сохранённой базой.
