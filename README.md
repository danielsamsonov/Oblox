# Oblox 2: бесплатный сервер в интернете

Подготовлен вариант **Render Free + Neon Free PostgreSQL**. ПК владельца не нужен после размещения. Сервер не считается запущенным, пока не получен настоящий публичный адрес и не проверены HTTPS/WSS, регистрация и сохранение после перезапуска.

## Бесплатные ресурсы

- Render: один web service с явно заданным `plan: free`, без постоянного диска, платной базы, worker и cron.
- Neon: отдельный проект на тарифе Free. Строка PostgreSQL передаётся в Render как секрет `DATABASE_URL`. В Git, APK и журналы она не попадает.
- `OBLOX_REQUIRE_DATABASE=1` запрещает облачному серверу запускаться с временным файловым хранилищем при отсутствии базы.
- `PAYMENTS=mock`: магазин использует тестовый режим.

Render Free засыпает после 15 минут без запросов. Первый вход после простоя может занять около минуты; клиент ожидает запуск и позволяет повторить попытку. Не используются фоновые запросы, имитирующие игроков для обхода сна. В рамках бесплатных квот доступность зависит от хостинга. Без привязанной карты Render при превышении бесплатных лимитов останавливает сервис. Не добавляйте карту или платные ресурсы, если нужны только бесплатные условия.

Данные аккаунтов, сессий, дружбы и опубликованных игр хранятся в Neon, поэтому перезапуск или сон Render их не стирает. Neon Free не имеет срока окончания пробного периода. При исчерпании вычислительных и сетевых квот база может приостановить доступ до сброса квоты; при заполнении хранилища новые записи не сохраняются. Бесплатный тариф не означает неограниченный объём. Точные текущие лимиты проверяются в панели Neon.

## Размещение

В корне серверного репозитория располагается `render.yaml`, а код — в `server/`.

1. Подключить Neon и создать проект **Free**, без карты и платного тарифа. Выбрать регион рядом с сервером Render.
2. Передать строку подключения PostgreSQL с TLS в секрет `DATABASE_URL` сервиса Render. Не публиковать её в переписке, исходниках или клиенте.
3. Создать web service **Free** в подтверждённом рабочем пространстве из репозитория `https://github.com/danielsamsonov/Oblox`, ветка `main`. Blueprint задаёт `rootDir: server`, `npm ci`, `node server.js`, `/api/health`. При прямом создании без rootDir команды: `cd server && npm ci` и `cd server && node server.js`.
4. Дождаться успешного развёртывания. Проверить `/api/health`, регистрацию двух временных пользователей, дружбу, публикацию, WebSocket-комнату и сохранение после нового запуска.
5. В клиенте на ПК и телефоне использовать один фактический адрес `wss://ИМЯ.onrender.com/ws`. Установщик или APK не должны содержать пароль базы.

Параметры сервера: Node.js 24 LTS; HTTP-порт из `PORT`; `OBLOX_DISCOVERY_PORT=0`; `TRUST_PROXY_HOPS=0`. Клиентские forwarding-заголовки не считаются доверенными без проверки цепочки proxy. Из-за этого лимит запросов авторизации за proxy может быть общим для нескольких игроков.

Репозиторий и архив включают только исходники. Личные локальные аккаунты и игры автоматически не переносятся в новую базу. Поддерживайте отдельные резервные копии базы перед существенными обновлениями.

## Локальный запуск

Без `DATABASE_URL` и без `OBLOX_REQUIRE_DATABASE=1` сервер сохраняет прежнее атомарное JSON-хранилище в `OBLOX_DATA_DIR` или `server/data`. Это подходит для локального запуска на ПК и не подходит для временной файловой системы бесплатного Render. Существующие личные данные не включаются в серверный архив.

`npm ci` устанавливает зависимости из lock-файла, `npm test` запускает проверки с отдельными временными данными. PostgreSQL имеет дополнительный интеграционный набор проверок; способ запуска описан в `server/README.md` после внедрения адаптера.

Официальные условия: [Render Free](https://render.com/docs/free), [Render FAQ](https://render.com/docs/faq), [Neon Free](https://neon.com/pricing), [планы Neon](https://neon.com/docs/introduction/plans).
